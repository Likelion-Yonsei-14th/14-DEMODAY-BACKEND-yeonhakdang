## 문서와 코드의 차이

1. 전달서·약관은 결제 즉시 통상 1분 내 개인화 유료 결과 생성을 약속합니다. 실제 코드는 유료 예시 화면입니다. 이를 완성된 계산기로 간주하지 않았으며 판매 준비를 기본 차단했습니다. 관리자 콘텐츠 등록 경계는 있으나 수작업 등록이 ‘1분 내 자동 제공’을 충족한다는 뜻은 아닙니다.
2. 전달서 P0-8은 주문 동의와 열람 후 환불 제한 동의 **두 개**입니다. `OrderPayment.tsx`는 하나만 구현했습니다. 카드 선택·미성년자 안내도 보완해야 합니다. 서버는 두 동의를 별도로 받아 모두 true이고 버전이 일치해야 주문을 만듭니다.
3. `lib/policies.ts`는 첨부 전문과 다릅니다. 환불 조문 일부가 생략·요약되어 있고, 표시와 다른 결과의 ‘제공 3개월/인지 30일’, 서비스 종료/탈퇴 조항 등이 동일하게 게시되지 않았습니다. 약관·처리방침은 자체 초안입니다. `draft:false` 표시가 원문·법률 검토 완료를 뜻하지 않습니다.
4. `lib/business.ts`의 대표자·등록번호·주소·연락처는 자리표시자입니다. 전달서의 상호·대표자·등록번호·주소·일반과세자·Vercel 정보와 대조하여 프론트엔드 담당자가 반영해야 합니다. 유선전화·고객센터 이메일·통신판매업 번호는 대표 확정이 필요합니다. 환불규정의 이메일은 다른 문서와 통일 여부가 미정입니다.
5. 전달서는 청소년보호정책 본문이 준비될 때까지 링크를 숨기라고 합니다. 현재 저장소에는 작성된 초안과 링크가 있습니다. 기획자 검토 전 공식 정책으로 취급하면 안 됩니다.
6. 정책 시행일은 **2026-10-29**이고 조사일은 10-28입니다. 서버의 `2026-10-29-draft`는 개발용 버전입니다. 실제 적용·게시·동의 버전은 운영자가 결정해야 합니다. 전달서의 10-31 일정·심사 소요 시간은 작성 당시 계획으로, 현재 달성/승인을 확인한 것이 아닙니다.
7. 기존 초대 링크는 생일·출생시간·이름을 **Base64URL**로 실어 보냅니다. 암호화가 아니며 주소·리퍼러·브라우저 기록·분석 서비스로 유출될 수 있습니다. 개인정보처리방침의 ‘친구에게 닉네임과 학과 결과’ 범위보다 넓습니다. 본 백엔드는 공개 공유 API나 해당 링크 저장을 추가하지 않았습니다. 기존 기능을 운영하려면 개인정보 없는 불투명 토큰, 명시적 공유 동의·철회·만료·범위를 먼저 결정해야 합니다.

## 배포 사이트 HTTP·초기 HTML 확인

실제 `https://yeonhakdang.vercel.app`에 로그인 없이 GET 요청했습니다. hash는 서버로 전송되지 않으므로 `/#1-1`의 HTTP 검증 경로는 `/`입니다.

| 경로 | HTTP | 확인 |
|---|---:|---|
| `/` | 200 | 가격 본문 존재, 대표자 자리표시자 존재, 실제 등록번호 없음 |
| `/products` | 200 | 상품·가격 본문 존재, 사업자 정보 미완성 |
| `/terms` | 200 | 정책 본문 존재, 사업자 정보 미완성 |
| `/privacy` | 200 | 정책 본문 존재, 사업자 정보 미완성 |
| `/refund` | 200 | 환불·가격 본문 존재, 사업자 정보 미완성 |
| `/about` | 404 | 전달서의 서비스 소개 경로 없음 |
| `/products/compat` | 404 | `/products#compat` 통합 페이지와 경로가 다름 |
| `/products/gwiin` | 404 | 통합 페이지의 `#benefactor`와 다름 |
| `/products/bujeok` | 404 | 통합 페이지의 `#charm`와 다름 |

전달서는 경로를 예시로 허용하므로 단순히 경로가 다르다고 심사 불합격을 단정하지 않습니다. 통합 상품 페이지가 구성·예시·고지 요구사항을 모두 만족하는지와 서비스 소개 대체를 사업자·PG가 확인해야 합니다. 실제 PG 콘솔 검사 결과, 계약 상태, 실도메인 소유·연결 상태는 접근하지 않았습니다. Figma 두 링크는 저장소 README와 전달서가 서로 달라 별도 열람/디자인 검증을 하지 않았습니다.
